# MoonFraming 设计说明

## 解决的问题

字节流不保留应用消息边界。一次读取可能得到半个长度前缀、半条载荷或多条连续消息。MoonFraming 将长度解析、暂存、资源限制和结束语义放进一个不依赖 socket 或异步运行时的状态机。

## 三种边界策略

默认 `Decoder` 使用有上界的 unsigned LEB128。小载荷通常只需一个长度字节，同时最多读取五字节，避免攻击者构造永不结束的前缀。

`LengthDelimitedCodec` 用于对接固定宽度长度头协议。一至四字节宽度、大小端、字段偏移、长度修正和跳过字节数可配置。这些配置足以表达常见的二进制 RPC、消息队列和数据库线格式。

`DelimiterDecoder` 用于 CRLF 等行协议或自定义结束标记。多字节分隔符可以跨输入块，返回结果可选是否包含分隔符。

当前最大值限定为 31 位。第五字节除最低三位外出现有效数据，或者五个字节都设置继续位时，解析返回 `MalformedVarint`。

## 增量状态机

`Decoder::feed` 使用头部和载荷两阶段状态，每个输入字节只解析一次。输入不足不是错误，半帧保留到下一次 `feed`。长度一旦可解析，就立即检查 `max_frame_size`。`max_buffer_size` 只计算尚未构成完整帧的数据，因此一个大输入块中的多条合法小帧不会被误判为超限。

调用方在确认输入结束时必须调用 `finish`。此时仍有残留字节会返回 `NeedMore`，从而把“等待下一批数据”和“文件或连接已经截断”区分开。

`reset` 只应在调用方知道新边界时使用，例如开始处理一条新连接。组件不会扫描任意字节猜测同步点，因为载荷内容可能与合法头部相同。

## 校验帧

校验格式把 IEEE CRC-32 放入长度包络，解码后比较载荷的实际校验值。CRC-32 用于发现偶发传输或落盘错误，不提供身份认证，也不能抵御主动篡改。

## 当前边界

- 不实现 socket、TLS、压缩、认证或业务协议。
- 完整载荷会拷贝到独立 `Bytes`，尚未提供借用切片或环形缓冲。
- 不提供损坏数据后的自动重新同步。
- 尚未绑定 MoonBit `Reader/Writer`；I/O 适配应放在独立包中，避免改变核心状态机语义。
